## 1. Автоматизация тестирования

В рамках текущего проекта была реализована инфраструктура для UI-автотестов на базе **Espresso** с использованием паттерна Page Object Model (POM) и принцип DRY.

### Технические достижения:

- **Idling Resources:** Для обеспечения стабильности тестов и исключения жестких задержек (`sleep`) в основной код приложения внесены изменения. Это позволило автотестам дожидаться завершения фоновых задач асинхронно.
- **Работа с API:** Проведен анализ исходящих HTTP-запросов через Android Studio Logcat. На основе захваченных эндпоинтов созданы вспомогательные методы в тестовом слое для подготовки данных и очистки состояния после прогона.
- **Сложности реализации:**
  - **Toast-сообщения:** Обнаружение всплывающих уведомлений Toast является известной архитектурной сложностью Espresso без дополнительных библиотек. Для авторизации реализован вывод текста ошибки внутри layout-экрана (под полями формы) для тестовых сборок. Автотесты переведены на проверку этих локальных View-компонентов вместо глобальных Pop-up окон.
  - **Определение категорий новостей:** У иконок категорий отсутствуют уникальные идентификаторы у графических ресурсов.
    **Реализованные решения:**
    1. **Экран «Новости»:** Применен метод прямого доступа к данным модели через модификацию адаптера (`NewsListAdapter.kt`). При активации флага `TestMode.isRunning()` текстовое название категории принудительно отображается в невидимом пользователю `TextView`. Это позволяет автотесту считывать категорию через стандартный матчер `withText()`, минуя анализ графики.
    2. **Экран «Панель управления»:** Поскольку поле с текстом категории отсутствует в верстке админки, реализован механизм Computer Vision (анализ Bitmap иконки). Данный подход позволяет обходить отсутствие id у графических элементов, однако делает тесты чувствительными к изменениям UI-контракта.

## 5. Дальнейшие шаги по развитию автоматизации

Проект имеет потенциал расширения покрытия до 100% сценариев Матрицы тестирования. Для оптимизации времени прогона и повышения стабильности рекомендуется внедрение гибридной стратегии тестирования:

- **Изоляция нестабильных сценариев (MockWebServer):** Внедрение `MockWebServer` точечно, только для проверки специфических состояний UI, не требующих реальной логики бэкенда:
  - Эмуляция пустых списков данных (`Empty State`) для проверки верстки заглушек.
  - Тестирование обработки сетевых ошибок (`HTTP 5xx`, `Timeout`), которые сложно вызвать на стабильном Stage-сервере.
  - Проверка доступности элементов интерфейса при отсутствии данных.
- **Сохранение End-to-End проверок:** Ключевые сценарии (*Happy Path*, создание/удаление новостей) должны продолжать тестироваться через реальный API для гарантии целостности контракта между клиентом и сервером.

## 6. Рекомендации по улучшению UX/UI

В ходе исследования пользовательского опыта были выявлены моменты, которые могут негативно влиять на удержание пользователей и удобство использования. Рекомендуется рассмотреть следующие улучшения:

### 1. Оптимизация глобальной навигации

- **Проблема:** Текущая реализация главного меню реализована через PopUp-меню, что нетипично для нативной навигации Android и перекрывает значительную часть экрана.
- **Рекомендация:** Заменить PopUp-меню на стандартный компонент `Navigation Drawer` (Drawer Menu). Это соответствует Material Design 3, освобождает пространство экрана, даёт предсказуемое поведение для тестов и позволяет масштабировать список пунктов меню без перегрузки интерфейса.

### 2. Логика иконки профиля

- **Проблема:** Нажатие на аватар пользователя в правом верхнем углу реализовано через PopUp‑меню, содержащее единственный пункт «Выйти». В нативных Android‑приложениях (согласно гайдлайнам Material Design) тап по аватару профиля обычно открывает экран с данными аккаунта. Текущая реализация не соответствует этому паттерну и снижает предсказуемость интерфейса.
- **Рекомендация:** При тапе по аватару выполнять переход на экран «Профиль». Кнопку «Выйти» перенести внутрь экрана профиля либо оставить в Navigation Drawer. Это соответствует Material Design и привычному UX для пользователей Android.

### 3. Оптимизация верхней панели AppBar

- **Проблема:** Иконка перехода к цитатам занимает постоянное место в `AppBar` (справа). Данный раздел содержит статический контент, обращение к которому происходит редко. При этом иконка постоянно занимает ценное пространство Top App Bar, где потенциально могут располагаться более приоритетные элементы (например, индикатор уведомлений или поиск).
- **Рекомендация:** Рассмотреть перенос пункта «Цитаты» из верхней панели в боковое меню (`Navigation Drawer`) как второстепенный пункт навигации. Это разгрузит интерфейс и соответствует паттерну размещения редко используемых ссылок в "гамбургер-меню".
